# Сервер

Перед запуском системы(созданием главного класса CarShopServer) происходит вариация конфига, если в конфиге допущены ошибки из-за которых система не сможет работать CarShopServer не создается и выводится текст с информацией об ошибке

## Класс ConfigValidator
Проверяет что в конфиге все названия моделей корректные и сервер сможет их заспавнить, проверяет что цена в допустимых переделах (прописываются в configValidationParameters в ServerConfig.ts), проверяет что цвет входит в список допустимых %%(на самом деле если цвет неправильный будет ставиться дефолтный и можно даже с неправильными значениями цвета в конфиге спокойно запускать систему продажи, но для однообразия тоже стопит запуск )%%. Проверяет что в конфиге нет одинаковых машин у которых разная цена (машины одинаковые могут быть выставлены на продажу только если они стоят одинаково)

## Класс CarShopServer
главный класс который создает instance для всех классов системы и распределяет зависимости этих классов (передает нужные instance в нужные классы для вызова методов из других классов которые им будут нужны)
Кроме создания instance реагирует на базовые ивенты (ивенты только тут и в классе контролирующем завспавненные игроками личные авто):
	resourceStart - отдает запрос на создание машин на продажу в соответствующий класс 
	playerConnect - выставляет координаты по которым спавнится игрок %%(дополнительно раньше передавал этому игроку конфиг)%%
	playerDisconnect - передает в класс следящий за игроками в аккаунтах запрос на удаление игрока из списка залогиненых (проверка на логин есть в самом классе)

### Класс AccountManager
Выполняет запросы от игрока (которые отправляются через класс с командами) связанные с аккаунтами: регистрация, логин
Выполняет все проверки на валидность данных при этих запросах (кидает throw new Error который ловится в классе с командами от которого был вызван метод)

Хранит в map (с ключом в виде entity alt.Player) список залогиненых игроков и их даные accountId и login %%в будущем можно еще нужные данные в нем хранить но пока что нужен только accountId для запросов в бд по первичному ключу и login для некоторых проверок%%

Взаимодействует с map и выполняет все проверки связанные с данными аккаунта и выполняет запросы в классы-бд на создание нового ползователя в бд и на получения данных пользователя из бд.

### Класс CommandManager
Регистрирует команды которые может делать игрок, проверяет валидность введенных аргументов и если все ок начинает try catch вызовы методов соответствующих командам классов

Отправляет игроку читаемые данные об успехе или причине неудачи вызванной команды

### VehiclesDataCollector
Общий класс необходимый всем остальным классам для получения нужных для их операций данных из AccountManager, VehicleDBRepository, VehiclesForSaleRegistry, PlayerVehiclesRepository. Что бы не передавать лишние завимости в другие классы и не повторять одни и те же действия для получения одних и тех же данных в других классах. Например половине классов нужен один и тот же метод на проверку владельца авто checkVehicleOwnershipAndCollectData, это делает VehiclesDataCollector и при фэйле проверки выводит корректный текст об ошибки проверки (С этой машиной нельзя выполнить эту операцию...)

### PlayerVehicleService
Класс для взаимодействия с автомобилями которые спавнил игрок(принадлежат игроку).
Проверяет данные через VehiclesDataCollector и если они прошли проверку выполняет действия по смене цвета на физическом варианте авто и передает эти цвета в бд для смены цветов в бд
Проверяет данные через VehiclesDataCollector и если они прошли проверку выполняет действия по смене текста на номерных знаках на физическом варианте авто и передает этот текст в бд для смены текста на номерном знаке в бд
### CarShopTradingService
aНужен только для продажи и покупки авто. Собирает/проверяет все нужные для покупки/продажи данные и передает из в CarShopDBTransactionManager
### Класс VehLifecycleManager
Контролирует все заспавненные игроками их личные машины из бд, и alt.Timeout на удаление неиспользуемых 
Долнительно имеет 3 ивент листенера на вход в авто (для очистки таймера на удаление), выход и авто (для создания таймера на удаление) и уничтожение авто (для очистки таймера на удаление)
